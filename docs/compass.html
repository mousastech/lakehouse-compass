Lakehouse Compass

A read-only, per-workspace check-up for your Databricks platform. Compass scans System Tables and platform APIs, scores your estate against the Well-Architected Framework, prioritizes findings with remediation, and now assesses Genie Ontology Readiness — all rendered in one AppKit app with an honest NOT AVAILABLE state wherever a source can't be read.

What is Compass #

Lakehouse Compass is a diagnostic application built on AppKit (Express + React 19 + Vite + Tailwind) that runs entirely on the Databricks platform. It answers a single question for a platform owner: “Is my workspace healthy, governed, and cost-efficient — and where do I fix it first?”

It never changes anything. Every collector is read-only; the agent proposes changes for a human with CAN MANAGE to approve, and execution happens outside Compass. Where a data source is missing or a grant is absent, the screen states exactly that rather than inventing a number.

Live app

The reference deployment runs on lakehouse-compass-7474658545709121.aws.databricksapps.com in the fevm-moi-ai workspace.

How it works #

Three moving parts, decoupled by Delta storage:

Scan job

A serverless Lakeflow job runs the collectors read-only against System Tables and platform APIs, per workspace, and appends results to Delta.

Delta store

Findings, scores, capabilities, cost, compliance and readiness land in moi_ai_catalog.lakehouse_compass.*, keyed by scan_id + workspace_id — history accrues.

AppKit app

Reads the latest scan per workspace through the analytics plugin, with a bundled-fixture fallback so every screen renders in demo or live mode.

The diagnostic runs per workspace. Every row carries workspace_id; the UI selector is URL-synced (?ws=) and each query reads the latest scan for the selected workspace, or an Account-mode roll-up.

Honest availability

A collector that can't read its source resolves that capability to NOT_AVAILABLE and yields no findings — never a fabricated score. Coverage (the share of usable capabilities) is shown alongside every health score so a high number backed by thin checking is never mistaken for proven health.

Well-Architected assessment #

Every rule maps to one or more pillars of the Databricks Well-Architected Framework. A finding penalizes each pillar it touches; a low rule count on a pillar surfaces as limited coverage so a high pillar score isn't over-read.

Genie Readiness NEW #

A faithful port of the open-source Genie Ontology Readiness assessment, integrated as a first-class Compass screen. It produces a 0–100 overall readiness score across seven weighted pillars — the UC Business Semantics foundation that feeds the learned Genie Ontology — each with a 0–4 maturity level, signals, gaps and gap-driven guidance.

Scores are deterministic functions of read-only technical signals (no self-assessment), so repeated scans of the same workspace are directly comparable.

What it reads

UC-metadata pillars use system.information_schema (or a per-catalog fallback when the metastore-wide view isn't granted) and are metastore-wide; the Genie and Adoption pillars are scoped to the selected workspace via system.access.audit and system.query.history. Any source that can't be read leaves that pillar NOT AVAILABLE with the exact grant needed — the score is never faked.

Each pillar with a gap also emits a GEN-READY-* finding (severity scaled by maturity level) mapped to the Data & AI Governance and Interoperability & Usability WAF pillars, so readiness gaps flow into Findings, the Well-Architected view and the weekly digest like every other domain.

Findings & compliance #

Findings are the atoms of Compass: one evaluated rule against one resource, with evidence, remediation and framework controls. Rules are declared in YAML; findings are written append-only per scan so history — new, resolved and still-open — is diffable between two scans.

  • Findings — searchable, filterable by domain and severity, with an evidence drawer.
  • Compliance — advisory mapping of findings to control frameworks (a mapping, not a certification claim).
  • Maintenance — recurring hygiene tasks generated from rules and scan freshness.
  • Digest — a plain-language “what changed and what to fix first”, optionally pushed to Slack.

Compass Agent #

A governed, read-only advisor on a Unity AI Gateway serving endpoint. It explains findings, prioritizes them, and drafts proposed changes with a rollback and a blast-radius estimate — citing finding and rule ids, respecting the selected workspace, and never executing. A reviewer with CAN MANAGE approves; the change is applied outside Compass.

Run & deploy #

Compass ships as a Databricks Asset Bundle. The app self-builds on Apps compute, so it deploys with the bundle — never databricks apps deploy. Order matters: run the scan first so the Delta tables exist before the app build introspects the warehouse.

# 1 · upload bundle (scan job + app source)
databricks bundle deploy -t dev -p fevm-moi-ai

# 2 · run the scan so the tables populate
databricks bundle run compass_scan -t dev -p fevm-moi-ai

# 3 · build + deploy the app (typegen sees the new tables)
databricks bundle run compass_app -t dev -p fevm-moi-ai
Environment notes

The catalog is moi_ai_catalog — main is not accessible in this workspace. The app build runs tsc strict, so unused imports fail the build. Business-hours automation stops the app off-hours; a redeploy restarts it.

Design principles #

Read-only by construction

Collectors only read. The agent proposes; humans dispose. Compass never executes a change.

Honest, never fabricated

A missing source is NOT_AVAILABLE with the exact grant needed — not a confident zero.

Per-workspace, with history

Every row is workspace-scoped and append-only, so trends and scan diffs are first-class.

Demo-first, live-ready

The same client renders bundled fixtures or live Delta, so a screen always shows a designed state.
