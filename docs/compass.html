What is Compass #

Lakehouse Compass is a diagnostic and observability app that runs entirely on the Databricks platform. It answers one question for a workspace administrator — “Is my workspace healthy, governed and cost-efficient, and where do I fix it first?” — without needing deep platform expertise.

It never changes anything. Every collector is read-only; the Agent proposes changes for a human with CAN MANAGE to approve, and execution happens outside Compass. Where a data source is missing or a grant is absent, the screen states exactly that instead of inventing a number. It runs in any workspace — the catalog is resolved per workspace, so onboarding a new one needs no code change.

Multi-language, admin-first

The whole UI is available in English, Português-BR and Español, and every finding offers an AI-generated, step-by-step “how to apply” — so an administrator who doesn't know the platform in depth can still act with confidence.

How it works #

Three moving parts, decoupled by Delta storage:

Scan

A serverless job runs the collectors read-only against System Tables and platform APIs, per workspace, and appends results to Delta. Trigger it on demand from the app, or on a schedule.

Store

Findings, scores, cost, usage, governance and readiness land in the Compass schema (<catalog>.lakehouse_compass.*), keyed by scan and workspace — history accrues over time.

App

A React app reads the latest scan for the selected workspace, with a demo fallback so every screen always renders. Language and workspace are switchable in the top bar.

Honest availability

A collector that can't read its source resolves that capability to NOT_AVAILABLE and yields no findings — never a fabricated score. Coverage (the share of usable sources) is shown next to every health score, so a high number backed by thin checking is never mistaken for proven health.

FinOps & cost observability #

Everything billed, made legible for an administrator: what is costing, how much, when and how it's used — all from system.billing.usage.

  • Cost over time — an evolutionary chart with a period filter (30d / 90d / 6M / 12M or a specific month) and monthly/daily granularity.
  • Breakdown & drill — a cost treemap by product; click through to resource, identity, effective owner and tags.
  • Unattributed drill — spend with no run-as identity (warehouses, apps, serverless jobs) is resolved to an effective owner, so “unattributed” is explained, not hidden.
  • Who is using it — top consumers ranked by cost and DBUs, with plain-language explanations of each metric.

AI Estate & AI Gateway governance #

For every model-serving endpoint, Compass shows a per-endpoint AI Gateway governance matrix and how it's actually being used.

  • Governance matrix — usage tracking, payload logging, rate limits and guardrails per endpoint, rolled up to a Governed / Partial / Not governed badge and a workspace-wide “% governed”.
  • Usage & who's using it — requests, distinct requesters, tokens and error rate from system.serving.endpoint_usage.
  • Drill — click an endpoint to see its full config plus the top requesters driving it.

Performance & compute inventory #

Beyond query latency, Compass inventories the compute that bills: SQL warehouses and interactive clusters, each with its configuration health (auto-stop, serverless, DBR version, auto-termination), 30-day cost, utilization and query volume — so idle or mis-configured compute is easy to spot.

Genie & Genie cost #

The Genie screen inventories Genie Agents and adds a cost & consumption view: the split between Genie Code and Genie Agents surfaces, free-vs-billed usage per user against the monthly free allowance, and cost/DBUs over time.

Well-Architected assessment #

Every rule maps to one or more pillars of the Databricks Well-Architected Framework. A control catalogue is scored per pillar as pass / gap / needs-validation, with a confidence band so a high score backed by few automated checks isn't over-read.

Findings & “how to apply” #

Findings are the atoms of Compass: one evaluated rule against one resource, with evidence, remediation and framework controls — searchable and filterable by domain and severity, written append-only per scan so history is diffable.

How to apply (AI)

Every finding has a “Teach me how to apply” action: it asks a governed Claude endpoint for concrete, numbered Databricks steps (UI paths, SQL, verification) to apply the fix — the learning-curve reducer for administrators. It's read-only guidance; Compass never executes.

  • Compliance — advisory mapping of findings to control frameworks (a mapping, not a certification claim).
  • Maintenance — recurring hygiene tasks generated from rules and scan freshness.
  • Digest — a plain-language “what changed and what to fix first”, optionally pushed to a channel.

Compass Agent #

A governed, read-only advisor on a serving endpoint. It explains findings, prioritizes them, and drafts proposed changes with a rollback and a blast-radius estimate — citing finding and rule ids, respecting the selected workspace, and never executing. A reviewer with CAN MANAGE approves; the change is applied outside Compass.

Reports & history #

  • Reports — a premium PDF per scan, generated on demand and stored in a Unity Catalog Volume, downloadable in-app.
  • History — an immutable snapshot per scan, so score/coverage trends and finding diffs (new / resolved / still-open) between two scans are first-class.
  • Self-check — Compass diagnoses its own posture (endpoint governance, least-privilege grants, scan freshness).

Design principles #

Read-only by construction

Collectors only read. The agent proposes; humans dispose. Compass never executes a change.

Honest, never fabricated

A missing source is NOT_AVAILABLE with the exact grant needed — not a confident zero.

Runs in any workspace

Every row is workspace-scoped and append-only; the catalog resolves per workspace, so onboarding a new one needs no code change.

Built to lower the learning curve

Multi-language UI, plain-language explanations and AI “how to apply” on every finding — so an admin doesn't need deep platform expertise.
